# 完成後の審査チェックリスト

動画を作り終えたら、渡す前にこのリストで審査します。[`PLAYBOOK.md`](./PLAYBOOK.md)（制作の決まりごと）と [`FACTCHECK.md`](./FACTCHECK.md)（事実確認）を、1項目ずつ確かめられる形にしたものです。

## 使い方

1. まず機械で確かめられる項目を流す（下の「機」の項目）。

   ```bash
   npm run review -- enyasu     # 回の名前を付ける
   ```

2. 残りを、動画を実際に再生し、止めながら確かめる（「目」は画面を見る、「耳」は音を聞く、「読」は資料を読む項目）。
3. 結果を回の資料（`〈回の名前〉.md`）に「審査の結果」として残す。日付、判定、★で落ちた項目、直したことを書く。

**判定のしかた**

- ★の項目が1つでも「いいえ」なら **不合格**。直すまで渡さない。信用と権利に関わる項目です。
- ★以外で「いいえ」があれば **条件つき合格**。渡すときに、どの項目が未達かを必ず伝える。
- 全部「はい」で **合格**。
- 確かめられなかった項目は「はい」にしない。「未確認」と書いて、渡すときに伝える（声は機械では聞けない、など）。

審査は、できれば作った本人以外がやります。本人しかいないときは、機械の結果と、止めた画面を根拠にします。記憶で「はい」を付けません。

## A. 情報は正しいか

| | 項目 | 確かめ方 |
| --- | --- | --- |
| ★ | 事実確認の報告（`FACTCHECK-〈回の名前〉.md`）があり、最後の判定が「合格」になっている | 機 |
| ★ | 確認役は、台本を書いた本人ではない | 読：報告の冒頭 |
| ★ | 報告で合格が出たあとに、台本・画面の文字・写真を変えていない。変えたなら、その分をもう一度確認に出したか、報告の最後に「確認役は見ていない変更」として書いてある | 読：報告の最後と、台本の変更履歴 |
| ★ | 完成した動画の字幕と画面の数字が、合格した台本と同じ（書き出しのときに古い台本や古い音声が混ざっていない） | 目：数字の出る場面を全部止めて、台本と照らす |
| ★ | 数字の出る画面すべてに、出どころが書いてある | 目 |
| ★ | 出どころの表記が、その資料に本当に書いてある内容と合っている | 読：報告の表 |
| ★ | 発言のかぎかっこの中は、報道の原文と一字一句同じ。報道によって言い回しが違う部分は、かぎかっこの外に出してある | 読：報告の表 |
| ★ | 番組の解釈には「わたしなりの読み」「ここは点線」「〜という見方」などの断りがある。地図では仮説が点線になっている | 目・読 |
| | 反対の立場やほかの理由にも触れている | 読 |
| | 報告の「人の目で確かめること」を、公開前に人が確かめた（まだなら、渡すときにその一覧を伝える） | 読 |
| | 作った日から公開日までに、相場や当局の動きなど前提が変わっていない | 読：その日のニュース |

## B. 台本は決まりを守っているか

| | 項目 | 確かめ方 |
| --- | --- | --- |
| | 構成が、掴み → 挨拶 → 今日の道のり（3か所）→ 3つの章 → 読み → まとめ → 視聴者への質問、の順になっている | 機 |
| | 番組名 Plotline と「今日は、〇〇がお送りします」を名乗っている | 機 |
| | 決まり文句「バラバラのニュースを、1本の線につなげる」があり、「線でつながりました」などを章ごとにくり返している | 機 |
| | です・ます調の話し言葉で、フレンドリーだが丁寧 | 読 |
| ★ | キャラクター特有の語尾（「〜なのだ」など）を使っていない | 機 |
| ★ | 参考動画の言い回しや決まり文句を、そのまま使っていない。話者になりすましていない | 読 |
| ★ | 1本の記事の言い換えになっていない（出典が複数ある） | 読：概要欄の出典 |
| ★ | 投資をすすめる表現がなく、最後に断り書きが出る | 目：最後の画面 |
| ★ | 未確認の疑惑（私生活など）を事実のように扱っていない | 読 |
| | たとえ話は1つ | 読 |
| | 用語に「ちなみに」の補足がある。初めて出る専門用語を、説明なしで使っていない | 機（補足の数）・読 |
| | 「ほかの意見」「残りは何か」など、見ていて気になることに答えている | 読 |
| | 1文は60字まで | 機 |
| | 似た数字を続けて出していない。出すなら関係を一度だけ言っている | 読 |
| | 数字が多すぎない（目安：1分あたり7個まで） | 機 |
| | 但し書きが多すぎず、結論がぼやけていない | 読 |

## C. 発言の紹介コーナー

| | 項目 | 確かめ方 |
| --- | --- | --- |
| | 「ここで、〇〇さんの声を聞いてみましょう」と振っている。どこの誰が、いつ、何について話したのかを言ってから発言に入っている | 耳・読 |
| ★ | 発言を足したり伸ばしたりしていない（もとが短い発言は短いまま） | 読：報告の表 |
| ★ | カードに出どころがある。外国語の発言は原文と「日本語訳は番組によるもの」が出ている | 機・目 |
| ★ | 読み上げが本人の声ではないと分かる表示（読み上げ：〇〇）がある。本人の写真や映像を使っていない | 目 |
| | 立場の違う声を両方入れている | 読 |
| | 発言の前（0.7秒）と後（0.9秒）に間がある。前の間のあいだに発言の文字が先に出る | 機・耳 |
| | 発言カードと字幕が重なっていない | 目：発言の直前と直後で止める |

## D. 声と間

| | 項目 | 確かめ方 |
| --- | --- | --- |
| | 声は VOICEVOX のずんだもんか春日部つむぎ。担当は乱数で決めた | 読 |
| | 設定が、抑揚0.93、読点の間1.15、速さ1.15 | 機 |
| | 全部の行に音声がある | 機 |
| | 読み間違いがない（「日本」「円安」、数字、人名、英字の略語） | 耳。聞けないときは `--kana` の読みを全行確かめ、「耳では未確認」と伝える |
| | 抑揚が強すぎない。不自然な区切りがない | 耳（機械では確かめられない） |
| | 視聴者への質問のあとに考える間（1.1〜1.3秒）があり、そのあいだ質問の字幕が出ている | 機・目 |
| | 数字や答えの直後、話の向きが変わる前、章の終わり、結論の直前に間がある | 耳 |
| | 音量が平均 −24〜−16dB、最大 −1dB以下。行によって大きさが違って聞こえない | 機・耳 |

## E. 見た目

| | 項目 | 確かめ方 |
| --- | --- | --- |
| ★ | 写真はすべて再利用できるライセンスで、撮影者とライセンスが画面と最後のクレジットに出ている | 機・目 |
| ★ | 写真の国・施設・時代が、話と食い違っていない（外国語の看板、別の省庁の表札、古い紙幣） | 目：写真を1枚ずつ開く |
| ★ | 関係のない個人の名前・電話番号・大きくはっきりした顔が写っていない | 目 |
| | 写真を使い回していない（1場面に1枚、全部ちがう） | 機 |
| | 写真の中の読める数字（値段、レート、年号）や社名が、話と紛らわしくない | 目 |
| | 図とグラフだけの画面が続いていない。人の気配のある写真を使っている | 目 |
| | 図は1場面に1つ。大きく見せる数字は1つ | 目 |
| ★ | 図の数値・棒の長さ・点の数が、台本の数字と合っている。残りの部分が別の意味に見えない | 目・読：報告の表 |
| | 文字が画面の端で切れていない。字幕・カード・図が重なっていない | 目：図の出る場面を全部止める |
| | 地図は周りの国・湖・経緯線・街の明かりがあり、ラベルが読める。確かな道のりは実線、仮説は点線 | 目 |
| | 配色がトピックに合っている（`palettes/index.html`）。主役色は画面の1割まで | 目 |
| | 書体は明朝体が主役、補助にゴシック | 目 |

## F. 仕上がり

| | 項目 | 確かめ方 |
| --- | --- | --- |
| | 長さを伝えた。9分を超えたら、削る候補も添えた（最初の希望は5分くらい） | 機 |
| | ファイルは100MB未満、1920×1080、30fps | 機 |
| | 最初から最後まで再生して、音が途切れる・絵が止まる・前の場面が残る、がない | 目・耳 |
| | 概要欄のチャプター時刻が、完成した動画と合っている | 目：各チャプターの頭に飛ぶ |
| | 概要欄に、出典、音声と地図と写真のクレジット、断り書き（投資の勧誘ではない、AIを使っている、資料写真、数字の時点）がある | 読 |
| | 回の資料（`〈回の名前〉.md`）と台本の表が、最新の台本と同じ | 読 |

## G. 進め方

| | 項目 | 確かめ方 |
| --- | --- | --- |
| | 頼まれていない版（英語版など）を作っていない | 読 |
| | 直したのは頼まれた範囲だけ。ほかに気づいた点は一覧にして渡した | 読 |
| | できていないこと・確かめられていないことを、渡すときに隠さず書いた | 読 |
| | 新しく受けた指摘を `PLAYBOOK.md` に書き足した。新しく見つかった誤りの型を `FACTCHECK.md` の例に書き足した | 読 |

```
- ★で「いいえ」だった項目：
- ★以外で「いいえ」だった項目：
- 未確認の項目（理由）：
- 直したこと：
```
