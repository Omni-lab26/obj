# Plotline 制作の決まりごと

これまでの動画づくりで出た指摘を、次の回でもそのまま使えるようにまとめたものです。新しい回を作るときは、最初にこのページを読みます。
指摘が増えたら、このページに書き足します。

最新の完成形は `release/denkidai-talk.mp4`（資料は [`TALK.md`](./TALK.md)）です。迷ったらこの動画に合わせます。

## 1. 進め方

- **いきなり動画を作らない。** 見た目や声を大きく変えるときは、先に HTML の見本ページ（雰囲気、声の聞き比べ、配色）を出して選んでもらう。「まだ作らないで」と言われたら、見本までで止める。
- **頼まれていない版は作らない。** 英語版は「作って」と言われたときだけ作る。日本語版を直したあとも、指示があるまで英語版は作り直さない。
- **直しは頼まれた範囲だけ。** 採点で見つけた改善点は一覧にして渡し、番号で指示されたものだけ直す。
- **返事は日本語で、短く、わかりやすく。** できていないこと、確かめられていないことは隠さず書く（声は聞けない、商標は調べきれていない、など）。
- 長さの最初の希望は「5分くらい」。補足や間を足すと伸びるので、伸びたときは必ず長さを伝えて、削る候補も添える。

- **台本ができたら、音声と動画を作る前に事実確認をする。** [`FACTCHECK.md`](./FACTCHECK.md) のプロンプトを、台本を書いていない確認役（別の会話か別のエージェント）に渡し、報告を `FACTCHECK-〈回の名前〉.md` に残す。「不合格」「条件つき合格」のあいだは音声も動画も作らない。信用に関わるので、ここは省かない。

## 2. 題材

- YouTube で伸びそうな、いま話題の経済ニュースを選ぶ。候補は大きく数本あげて、理由と合う配色を添える。
- 直近のニュースだけでなく、長く見られそうな題材の候補も [`TOPICS.md`](./TOPICS.md) にまとめてある（30本）。
- 1本の記事の言い換えにしない。複数の報道と一次資料から組み立てる。
- 投資をすすめる内容にしない。動画の最後に断り書きを入れる。
- 未確認の疑惑（私生活、スパイ疑惑など）は扱わないか、「報道ベース」と断って経済への影響に絞る。

## 3. 台本

**構成**

掴み → 挨拶 → 今日の道のり（3か所）→ 3つの章 → 「ボクなりの読み」→ まとめ → 視聴者への質問、の順。

**番組名と決まり文句**

- 番組名は **Plotline**（読みは「プロットライン」）。
- 「頭の中でバラバラになってるニュースを、1本の線につなげる番組です」を軸に、「線でつながりました」「1本の線につなげます」「また次の線で」など、同じ言い回しを何度も使う。

**口調**

- です・ます調の話し言葉。フレンドリーに、でも丁寧に。
- 参考動画の口調（テンポ、問いかけ方）は取り入れるが、言い回しはそのまま使わない。参考チャンネルの決まり文句は使わない。話者になりすまさない。
- キャラクター特有の語尾（「〜なのだ」など）は使わない。声だけを借りる。

**中身**

- 数字には出どころを付ける。自分の解釈には「ここは点線」「ボクなりの読み」と断りを入れる。
- たとえ話は1本につき1つ（電気代の回は「町内会とお屋敷」）。
- 文字と図に全部を載せない。見る人の頭がいっぱいにならない量にする。

**痒いところに手が届く補足（「ちなみに」）**

- 知識があいまいな人のために、用語にひとこと足す（データセンター、中間選挙、指数の名前、卸値、連銀、上院・下院、社債、地名など）。
- 「ほかの意見は何だったのか」「残りの1件はどこか」のように、見ていて気になることに先回りして答える。
- 賛成側と反対側、主な説とほかの説の両方を出す。

**わかりやすさの決まり**（[`CLARITY.md`](./CLARITY.md) の採点から）

- 似た数字を続けて出さない（「45件」と「47件」）。出すなら関係を一度だけ言う。
- 1文は60字まで。超えたら2つに割る。
- 但し書きは必要な数にしぼり、結論がぼやけないようにする。

## 4. 発言の紹介コーナー

- 「ここで、〇〇さんの声を聞いてみましょう」と振って、実際の発言をカードで見せる。
- 紹介は少し長めに。どこの誰が、いつ、何について話したのかを言ってから発言に入る。
- 発言は報道に引用符つきで載っているものだけ。原文と出どころをカードに入れ、日本語は番組の訳だと明記する。
- **発言は足したり伸ばしたりしない。** もとが短い発言は短いままでよい。
- 読み上げはもう一人の担当の声で、本人の声ではないと表示する。本人の写真や映像は使わない。

## 5. 声

- VOICEVOX の **ずんだもん** と **春日部つむぎ**。担当は回ごとにランダムで決め、「今日は、〇〇がお送りします」と名乗る。
- 設定は、抑揚 **0.93**、読点の間 **1.15**、速さ 1.15（`scripts/tts_voicevox.py` の既定値）。
- 不採用になった声：Kokoro（日本語）は不自然、Style-Bert-VITS2 も喋り方が変、という評価。
- 読み間違いは `--kana` で確かめ、`say` で直す（例：「日本」→「にほん」、数字、外国の人名）。

## 6. 間の取り方

セリフの間は `src/talk/pacing.ts` で1行ずつ決める。人が相手に話すときに自然に空く場所で待つ。

| 場所 | 足す長さ |
| --- | --- |
| 発言を紹介する直前（この間に発言の文字を先に出す） | 0.7秒 |
| 発言を読み終えた直後（カードは見せたまま） | 0.9秒 |
| 視聴者に質問した直後（質問の字幕は出したまま） | 1.1〜1.3秒 |
| 数字や答えを言った直後 | 0.6秒 |
| 話の向きが変わる前（「ただ」「ちなみに」） | 0.45秒 |
| 章の終わり | 0.85秒 |
| 結論を言う直前 | 一拍 |

## 7. 見た目

- 雰囲気は「写真ドキュメンタリー」。書体は明朝体（Shippori Mincho）が主役、補助にゴシック（Noto Sans JP）。
- **実際の写真を使う。** ありがちな図とグラフだけの画面にしない。人の気配がある写真を選ぶ。
- **写真は使い回さない。** 1場面に1枚、全部ちがう写真にする。
- リポジトリが公開なので、写真は再利用できるライセンス（CC BY、CC BY-SA、CC0、パブリックドメイン）だけ。撮影者とライセンスを画面と最後のクレジットに出す。写真の場所が話と食い違わないか確かめる（アメリカの話にカナダの建物を使わない）。写真の題名だけでなく、写り込んだ看板や文字も見る（財務省の話に総務省の看板が写った写真を使わない）。
- 図と地図は自作してよい。図は1場面に1つ、数字は1つだけ大きく見せる。
- 写真は題名だけで選ばない。開いて見て、読める数字・社名・個人名・大きな顔・年号・違う国の文字がないか確かめる。お札や硬貨はなるべく今のデザインのものを使う。
- 地図は質を高く（周りの国、湖、経緯線、街の明かり）。確かな道のりは実線、仮説は点線。
- 配色は目を引くが、くどくしない。主役色を使うのは画面の1割まで。
- **色はトピックごとに変える。** 選び方は `palettes/index.html`（配色リスト）を見る。台本に `"palette": "…"` を書くと切り替わる。

**サムネイル**

- **採用された型**（1ドル160円の回）：明朝体の大きい数字を主役の色で1つ、その上に小さく前置き（「1ドル」）、下に光る線と番組の題を明朝体で2行、背景は話に合う写真を暗く重ねる、左上に「Plotline」と担当。番組の写真ドキュメンタリーの雰囲気のまま作る。
- 太いゴシックに縁取りをした「よくあるプロ風」の型、切り抜いた硬貨を置く型、線や地図を主役にする型も作ったが、採用されなかった（2026年11月）。まずは採用された型で作り、別の型は頼まれたときに出す。
- 文字は事実確認で合格した内容だけにする。サムネイルの文字も確認役に見せる。番組の読み（題）を事実のように言い切らない。
- 小さく表示しても読めるか、スマホの大きさに縮めて確かめる。
- 写真のクレジットは画面に入らないので、概要欄に書く。

## 8. 仕上げの確認

- **作り終えたら、渡す前に [`REVIEW.md`](./REVIEW.md) の審査チェックリストを通す。** 機械で確かめられる項目は `npm run review -- 〈回の名前〉` で流し、残りは動画を止めながら確かめる。★の項目が1つでも落ちたら渡さない。結果は回の資料に残す。

- 事実は1か所ずつ裏を取り、[`ACCURACY.md`](./ACCURACY.md) の形で採点する（複数の報道で確認できたか、解釈が入っていないか）。
- わかりやすさは [`CLARITY.md`](./CLARITY.md) の7つの観点で採点する。
- 書き出したら、画面の重なり（字幕とカード）、読み方、長さ、音量を確かめる。
- 声の聞こえ方は機械では確かめられないので、抑揚と間は必ず耳で確認してもらう。

## 9. 作業メモ（作る側向け）

- 回ごとのファイルは `src/talk/〈回の名前〉.lines.json`（台本）、`.shots.ts`（画面）、`.pacing.ts`（間）、`.voice-manifest.json`（音声の長さ）。`REMOTION_EPISODE=〈回の名前〉` を付けて `Talk` を書き出す。新しい回を足すときは `episode.ts`、`episodes.ts`、`lang.ts` に1行ずつ足す。

- 書き出しは1本およそ20分。始める前に、ほかの書き出しが動いていないことを確かめる。台本を変える指示が来たら、動いている書き出しを止めてから直す。
- 地図の下絵は先に画像にしておく（`npm run maps:talk`）。毎フレーム描くと極端に遅くなる。
- 英語版は `REMOTION_LANG=en`。画面の文字に英訳がないと書き出しが止まるので、先に全部の文字を確かめる。
- 完成動画は GitHub の上限（100MB）を超えないようにする。10分で約95MB。
- 音声ファイルを作り直したら、長さの一覧（`voice-manifest.json`）も更新される。概要欄のチャプター時刻は毎回計算し直す。
