# 確かめ方

<!-- AI の「完了」を、どこまで自動で信じてよく、どこから実機で見るかを分けておく。 -->

## 1. 自動（毎回・AI が自分でやる）
| コマンド | 中身 |
| --- | --- |
| `npm run verify` | 型チェック・lint・整形・テスト |
| `node scripts/shot.mjs <ルート…>` | Web 書き出しを幅 320 / 393 / 440 で撮影し、`.artifacts/shots/` に保存 |
| CI | push のたびに `npm run verify` |

### テストを必ず書くもの
- {フロントのみ}画面幅・文字の位置などの計算をする純粋関数
- {バックエンドあり}中心の流れ：記録 → 保存 → 再読み込み → 表示、課金の有無による権限、日付・時間の計算

## 2. ブラウザ（Web 書き出し）で確かめてよいこと
- レイアウトの大まかな崩れ、画面の有無、遷移
- 文字の切れ・重なり（ただし描画の細部は実機と違う）

## 3. 実機でしか分からないこと
<!-- プロジェクトごとに足していく。ここに当たる変更は、AI が「確かめてほしい点」を3行で伝える。 -->
- 文字の描画の細部（基準線、細い字、拡大したときの荒れ）
- 端末の言語での表示（日本語の端末で日本語になるか）
- 振動、ジェスチャーの気持ちよさ、スクロールの滑らかさ
- safe area・ホームインジケーター・Android のナビゲーションバーとの干渉
- すりガラス（ぼかし）の効き方、ダークモード
- 文字サイズの設定（Dynamic Type）を最大にしたとき
- アイコン・起動画面（キャッシュに注意：削除 → 再起動 → 入れ直し）
- 通知、ウィジェット、バックグラウンド動作、課金

## 4. 実機で確かめる区切り
- フェーズ3：空の画面が開く（Expo Go の SDK の版も確認）
- フェーズ4：開発用ビルド／TestFlight で起動、日本語で表示
- 機能を1つ作るたび
- 公開の前
