# キックオフ・プロンプト

新しいプロジェクトを始めたら、最初にこれを AI に貼ってください。
`{ }` の部分は、分かる範囲で埋めてから貼ります。分からないところは空のままで構いません（AI が質問します）。

---

```
新しいアプリを始めます。まだ実装はしないでください。
最初の仕事は、作り始める前に決めるべきことを決めて、docs/ の雛形を埋めることです。

【いま分かっていること】
- 作りたいもの：{1〜3行で}
- 参考（アプリ・画像・動画）：{あれば}
- 期限・公開の予定：{あれば}

【進め方】
1. CLAUDE.md と docs/ の雛形をすべて読んでください。
2. docs/brief.md の空欄を埋めるために、AskUserQuestion で私に質問してください。
   特に次は必ず聞いてください。過去のプロジェクトで、後から決めて大きな手戻りになったものです。
   - 目的は「見本の再現」か「良いプロダクト」か
   - MVP の3機能と、やらないこと
   - 完成の基準（確かめられる形で）
   - アプリ名・bundle ID・slug（仮でよい）
   - 無料か有料か、価格、配信する国
   - 対応範囲：画面幅、iOS / Android / Web、文字サイズ、ダークモード、縦固定、タブレット
   - 使うネイティブ機能（Expo Go で足りるか、開発用ビルドが前提か）
   - バックエンドの有無
3. brief.md を書いたら、厳しい評価者として企画を採点し、MVP をもっと絞る案があれば出してください。
4. 私が brief.md を承認したら、docs/screens.md（と、バックエンドがあれば docs/data-model.md）の案を作ってください。
   行き止まりの画面、同じ操作がぶつかるところ、権限があいまいなところを指摘してください。
5. それも承認したら、docs/design.md の方向性を決めるために、主要3画面を2〜3案描いて画像で見せてください。

各段階で承認を待ってください。承認された内容は docs/decisions.md に日付付きで記録してください。
返事は日本語で、専門用語は言い換えてください。
```
