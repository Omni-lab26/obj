# プロンプト：Inchly を「人が作ったアプリ」に作り直す

## 役割

あなたは、日本の学生向けアプリを何本も出してきたプロダクトデザイナー兼 React Native エンジニアです。
Studyplus・Forest・Apple フィットネス・Strava・GitHub のような「使う人の生活が見える」アプリを作ってきました。
いまの Inchly（Expo 版）は、見た目は整っているのに「AI が作った感じ」が残っています。
小手先の調整ではなく、プロとして大胆に作り直してください。

## 入力

- 現在の全画面スクショ：`docs/screenshots/expo-all/`（ライト23枚・ダーク6枚）
- コード：`inchly-app/`（Expo SDK 57 / Expo Router）
- 守るべき既存の決まり：
  - 中立の背景、勉強の記録だけが緑
  - bencho の4部品（stacked bars / pull / time scrubber / rolling counter）
  - グループチャットに画像は出さない（画像は「共有」タブだけ）
  - 既存の機能は消さない（置き場所は変えてよい）

## 手順

### 1. 採点する（200点満点）

次の10項目を各20点で採点し、合計と「AI感（100点満点、高いほど AI っぽい）」を出す。
点数ごとに、根拠になった画面名を必ず書く。甘く付けない。

| # | 項目 | 何を見るか |
| --- | --- | --- |
| 1 | 情報の優先順位 | 1画面で一番大事なものが一目でわかるか。機能の並べっぱなしになっていないか |
| 2 | 画面ごとの構成の違い | どの画面も「大見出し＋右に灰色の補足＋行リスト」の同じ型になっていないか |
| 3 | データのリアルさ | 毎日全科目を勉強している、数字が丸い、名前が全員ひらがな2文字、などの作り物感がないか |
| 4 | 言葉の人間味 | 操作の説明文を画面に書きすぎていないか。学生が実際に使う短い言葉か |
| 5 | 色と装飾の抑え | 科目の虹色・色付きの点を使いすぎていないか |
| 6 | 写真・中身のある素材 | 文字アイコンと線の絵だけで、実物の写真やノートが一つもない状態になっていないか |
| 7 | ブランドの個性 | アプリ名・言葉づかい・この製品にしかない形があるか |
| 8 | 重複のなさ | 同じ操作や同じグラフが何か所にもないか（タイマー操作、草、検索・通知アイコン） |
| 9 | ディテールの仕上げ | 揃え・余白・数字の書体・空の状態・端の処理 |
| 10 | 動きと手ざわり | 押した感じ、つながった動き、振動 |

### 2. 問題点を書き出す

「AI っぽさの原因」を具体的に列挙する。

- 例：「どのセクションにも右上に灰色の補足文がある」「ホームにタイマー操作が3つある」
- それぞれに、直す画面と直し方を書く。

### 3. 大胆に直す

方針は次のとおり。迷ったら「実在の学生が毎日開くアプリならどうなっているか」で決める。

1. **ホームを削る**
   - 一番上は「今日の勉強」だけを主役にする。
   - 勉強中はその主役がそのまま勉強中の表示に変わり、別のボタンやバーを重ねない。
   - 科目チップ・週の帯・18週の草はホームから外す。草は記録とマイページのカードに任せる。
   - 締切は一番近い1件だけにする。
2. **同じ型をやめる**
   - 見出しの右の灰色補足は、押せるときだけ置く。
   - 画面ごとに主役の形を変える：
     - ホーム：今日の数字と目盛り
     - 記録：一文の要約とグラフ
     - みんな：自習室のような顔の並び
     - マイページ：カード
3. **データを本物っぽくする**
   - 休んだ日、テスト前に増える週、1日に1〜3科目だけ、端数のある数字にする。
   - 名前はニックネーム・英字・絵文字が混ざった実在しそうなものにする。
   - 投稿は長さも口調もばらばらにする。
4. **説明文を消す**
   - 「〜をドラッグして〜」「〜を押すと〜」「〜に表示されます」の類は原則すべて消す。
   - 必要なら初回だけのヒントか、触れば分かる形にする。
   - 言葉は短く、学生の口調に寄せる。
5. **色を絞る**
   - 科目色は彩度を落とし、グラフの中だけで使う。
   - リストやチップの色付きの点はやめて、文字か形で区別する。
6. **写真を入れる**
   - プロフィールアイコンは写真にする。学生らしく、ペット・空・花・飲み物など顔以外を中心にする。
   - 共有ノートと読みものにも写真を入れる。
   - 文字アイコンは「写真を設定していない人」にだけ残す。
   - 写真のクレジットを残す。
7. **ブランドを一つ持つ**
   - 名前の由来「inch（少しずつ）」から、目盛り（ルーラー）をこの製品の形にする。
   - タイマーのルーラーとホームの進み具合を同じ目盛りでつなぐ。
   - ホームの左上に名前を置く。
8. **重複を消す**
   - タイマー操作：ホームでは主役に統合する。下の再生ボタンは、勉強中は「いま何分」の表示に変える。
   - 検索・お知らせのアイコンは、必要な画面にだけ置く。
9. **仕上げ**
   - 写真のある行・ない行の揃え、長い名前の省略、空の状態、ダークモードでの写真の見え方を確認する。

### 4. 確認する

- 型チェック・lint・iOS / Android の書き出しがすべて通ること。
- 全画面を撮り直し、直す前と後を並べた画像を作ること。
- 同じ表で採点し直すこと。
  - 甘い採点はしない。200点に届かなかった項目は、何が足りないかを書く。
  - 直せないもの（実機でしか確かめられない等）は、正直に「未確認」と書く。

## 出力

- 採点表（直す前・直した後）と問題点の一覧：`docs/design/humanize-audit.md`
- コードの修正（コミットして push）
- 直す前と後のスクショ比較
