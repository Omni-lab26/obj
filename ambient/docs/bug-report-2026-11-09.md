## 2. 1件ずつの詳細

### B-01（S1）数字を動かして「完了」を押すと数字が消える

**再現手順**
1. ペンを押して編集に入る。
2. 1本指で数字を少し動かす（触れて、動かさずに離すだけでも同じ）。2本指で大きさを変えた場合は起きない。
3. 「完了」を押す。

**期待した動き**：数字が新しい位置に残る。

**実際の動き**：数字の行だけが不透明度 0 になり、見えなくなる。日付・ヒント・背景・ボタンは残る。タップしても、モードを左右に切り替えても見えない（どのモードでも同じ数字の行が使われるため）。もう一度ペンを押すと編集中だけ見え、「完了」でまた消える。戻すには、大きさを変えて「完了」するか、アプリを入れ直す（再起動）しかない。

**証拠**：`docs/bug-report-2026-11-09/vanish.png`（完了直後。日付だけが残り、数字がない）。
テストの記録（`hunt/t_follow3.cjs`）：
```
V1 after drag (editing)   maxOpacity 1
V1 after Done             maxOpacity 0   face {x:0, y:0.0758, scale:1}
V1 after swiping to the timer   maxOpacity 0
V1 editing again          maxOpacity 1
V1 Done again             maxOpacity 0
V1 after a pinch + Done   maxOpacity 1   （大きさを変えると戻る）
V2 touch without moving + Done   maxOpacity 0
V4 timer: drag + Done     maxOpacity 0
```
2本指で広げてから元の大きさに戻して離した場合（倍率がちょうど 1）も同じく消える（`t_final.cjs`）。

**原因**：`src/Clock.tsx`
- 指を離すと `done` が呼ばれ（926-933 行）、止まった後のくっきりした数字（`restK` のコピー）を重ね、`stillOn` を 1 にする。`stillOn` が 1 のあいだ、動く方の数字は `digitsStyle`（730 行）で不透明度 0 になる。
- `stillOn` を 0 に戻すのは 717-725 行の反応だけで、条件は「指が触れている」か「`zoom` が `stillK` からずれた」とき。
- 移動だけ（倍率 1）で「完了」すると、`commitEdit` のあとも `zoom` は 1、`stillK` も 1 なので反応が起きず、`stillOn` が 1 のまま残る。くっきりした方のコピーは `framed && edit` のときしか描かれない（1016 行）ので、編集を抜けた瞬間に両方とも見えなくなる。
- 大きさを変えた場合は、`commitEdit` 後に `zoom.set(1)` で `stillK`（≠1）からずれるため反応が起きて戻る。

**直し方の見当**：編集を終えるとき（`edit` が false になる効果、915-924 行）や `commitEdit` で `stillOn.set(0)` と `setRestK(null)` を行う。1〜3行。

**1.0 にもあるか**：なし。`stillOn` は 11月3日の `27b4c02` で入った。

### B-02（S2）背景の WebView が裏で終了させられたとき戻らない（要実機）

**筋道**：背景は `react-native-webview` の `WebView` で動く（`src/SceneView.tsx:53`）。iOS はメモリが足りないときや長く裏にあったアプリの WKWebView のコンテンツプロセスを終了させることがあり、そのとき WebView は空白になる。`react-native-webview` はこれを `onContentProcessDidTerminate` で知らせるが、`SceneView.tsx` はこの prop を渡していないので、再読み込みされない。アプリに戻ると、背景の場所は `containerStyle` の背景色（`scene.background`）一色のまま、時計だけが動く。背景を切り替えれば新しい WebView が作られて直る。

**実機での確かめ方**：3章を参照。

**直し方の見当**：`onContentProcessDidTerminate={() => ref.current?.reload()}` を足す。`reload` は `WebViewHandle` の型に追加が必要。

**1.0 にもあるか**：あり。

**1.0 にもあるか**：あり（`89ea1a3`、10月30日）。

### B-04（S3）セリフ体・グロテスク体で数字が左右に揺れる

**再現手順**
1. フォントを「セリフ」または「グロテスク」にする。
2. 時計で「秒」をオンにして見る。または、ストップウォッチを動かす。

**期待した動き**：秒や 0.1 秒の桁だけが変わり、ほかの数字は動かない。

**実際の動き**：秒が変わるたびに（ストップウォッチでは 0.1 秒ごとに）数字の行全体が左右に 2〜3 px ずれる。細かく震えて見える。

**証拠**（`t_jitter.cjs`、コロンの左端の動き）：

| フォント | 時計・秒オン（4秒間） | ストップウォッチ（1.5秒間） |
| --- | --- | --- |
| セリフ | 3.27 px | 2.19 px |
| グロテスク | 2.83 px | 2.32 px |
| 標準・まる・コンデンス・モノ・ドット・ターミナル | 0 | 0 |

**原因**：`src/Clock.tsx:418-431` で大きい数字は1桁ずつ固定幅のマス（`cell`）に入れているが、秒・0.1 秒の小さい文字（432-449 行の `small`）はマスに入れていない。幅が桁ごとに違うフォントでは小さい文字の幅が変わり、行全体が中央寄せなので、その半分だけ全体がずれる。

**直し方の見当**：`small` も1桁ずつ `digitPerPt * drawn * secondsScale` の固定幅のマスに入れる（`rowWidth` はすでにその前提で計算している）。

**1.0 にもあるか**：あり（同じ構造。`9e34a2d` 時点の `Clock.tsx` 435-450 行）。

### B-05（S3）端末の時計を戻すとストップウォッチがマイナスになる

**再現手順**
1. ストップウォッチを開始する。
2. 端末の日時を過去に変える（自動設定を切って手で戻す）。
3. 数字をタップして止め、もう一度タップして再開する。

**期待した動き**：止めた時点までの経過がそのまま残り、再開すればそこから進む。

**実際の動き**：動作中は 00:00:00 で止まったように見える。止めると経過がマイナスになり（1時間戻した例で `elapsed: -3597729`）、再開してもマイナス分を食いつぶすまで 00:00:00 のまま動かない。ヒントも空のまま。

**証拠**（`t_stopwatch.cjs`、Playwright の時計で1時間戻した）：
```
D2 after set back (running)  00:00:00
D2 stopped   {"startAt":null,"elapsed":-3597729}
D2 restarted {"startAt":1794574823262,"elapsed":-3597729}  表示 00:00:00
```

**原因**：`src/timers.ts:56` の `toggleStopwatch` が `elapsed + (now - startAt)` をそのまま保存し、`now < startAt` を考えていない（表示側の `stopwatchElapsed` だけ `Math.max(0, …)` で守っている）。`src/Clock.tsx:545` の 0.1 秒表示 `Math.floor((e % 1000) / 100)` もマイナスだと `-8` のような値になる（表示では `e` が 0 に丸められるので出ないが、経過が負のあいだ `.-x` になる経路は残る）。

起きるのは端末の時刻を手で変えたときだけ（時差の移動や夏時間では `Date.now()` は変わらない）なので S3。

**直し方の見当**：`toggleStopwatch` で `Math.max(0, now - s.startAt)` を使う。タイマーの `toggleTimer` は `Math.max(0, …)` 済み。

**1.0 にもあるか**：あり（`69549f7`、10月29日）。

### B-06（S3）文字サイズ設定（Dynamic Type）が全文字に効く（要実機）

**筋道**：React Native の `Text` は既定で `allowFontScaling` が true。このアプリでは `allowFontScaling` も `maxFontSizeMultiplier` もどこにも指定していないので、iOS の「文字サイズ」を大きくすると、数字・日付・ヒント・設定画面・背景切り替えの文がすべて拡大される。

- 数字：幅の計測も同じ倍率で拡大されるので崩れない。ただし「最大の大きさ」も大きくなり、画面に収まる上限（`fit`）がそのぶん小さくなる。
- 背景切り替えの帯（`App.tsx:328-337`）：`numberOfLines={1}` なので、大きい設定では「…」で切れる。
- 設定画面：タイル（高さ 62）やフォントのタイル（高さ 86）は固定なので、大きい設定では文字がはみ出すか重なる。

**実機での確かめ方**：3章。

**直し方の見当**：数字以外の `Text` に `maxFontSizeMultiplier={1.3}` 程度を付ける（または全体で `Text.defaultProps` 相当を設定する）。

**1.0 にもあるか**：あり。

### B-07（S4）保存データの言語が ja/en 以外だと起動時に落ちる

**再現手順**：`ambient.settings.v1` に `{"lang":"fr","langChosen":true}` を入れて起動する（ウェブ版の localStorage。実機ではアプリが書く値しか入らないので、ふつうは起きない）。

**実際の動き**：`Cannot read properties of undefined (reading 'clock')` で描画が止まり、白画面。

**原因**：`src/Clock.tsx:829` の `HINT_W[lang][mode]` が `HINT_W['fr']` で undefined になる。`useT()` は `STRINGS[lang] ?? STRINGS.ja` で守っているが、こちらは守っていない。`src/settings.tsx:85` の `withDefaults` も `lang` の値を確かめない。

**直し方の見当**：`withDefaults` で `lang` が `ja`/`en` 以外なら `deviceLang()` に戻す。

**1.0 にもあるか**：あり。

### B-09（S4）神社：約16分40秒ごとに文字が一斉に入れ替わる

**再現手順**：神社の背景を 16 分 40 秒（1000 秒）見続ける。テストでは `#hold&probe` で `Host.time` を 999.95 → 1000.0 に進めて比べた。

**実際の動き**：ふだんは1フレームで画面の約 9 % の画素が変わる（文字の入れ替わりのゆらぎ）のに対し、1000 秒の折り返しをまたぐフレームでは約 16 % が変わる（`t_shrine_wrap.cjs`：`changedFrac 0.0908 → 0.1593`、平均差 `13.0 → 23.8`）。全画面の文字が同じ瞬間に入れ替わるので、一瞬だけ画面全体がちらつく。配置や色は変わらない。

**原因**：`scenes/shrine.html:1223` で `uT` に `t % 1000` を渡している。シェーダー（192 行）の入れ替えの拍子 `k = floor(uT * rate + ph)` が折り返しで全セル同時に変わる。灯籠の炎の位相（174 行）も飛ぶ。風と雲（`uWind`, `uCloud`）は繰り返しテクスチャの座標なので折り返しても飛ばない。

**直し方の見当**：`t % 1000` をやめて、拍子の計算を CPU 側で周期的にするか、`uT` の折り返し周期を各 `rate` の公倍数にする。または float の精度が足りる範囲（数時間）まで折り返しを伸ばし、折り返しを再起動時に寄せる。

**1.0 にもあるか**：なし。

### B-10（S4）長押しで時計を隠すとき、エサ・驚かし・落ち葉も起きる

**筋道**：`scenes/shared/host.js:134-149` は `pointerdown` の時点で `scene.tap(x, y)` を呼び、そのあと 520 ms 押し続けていれば `longpress` を送る。つまり長押しの最初の瞬間にタップの効果（鯉ならエサ、魚の近くなら驚かし、神社なら落ち葉の舞い上がり、通りすがりなら逃げる）が必ず起きる。時計を隠すつもりで長押しすると、毎回背景が反応する。

**直し方の見当**：`scene.tap` を `pointerup`（長押しにならなかったとき）に移す。ただし反応が指を離すまで遅れるので、好みの問題。

**1.0 にもあるか**：あり。

### B-11（S4）一時停止中のタイマーでも目盛りが使え、残り時間が捨てられる

**再現手順**：15 秒のタイマーを開始し、途中でタップして一時停止（残り 11.7 秒）。分の目盛りを1分ぶん動かす。

**実際の動き**：目盛りはそのまま見えていて動かせる。動かすと `duration = left = 75000`（1:15）になり、残り 11.7 秒は捨てられる。ヒントは「タップで再開・長押しでリセット」のまま。

**原因**：`src/Clock.tsx:625-626` の `timerIdle` は「動いていない・終わっていない」なので一時停止も含み、`setting` が true になる（1164 行で目盛りがタッチを受ける）。コードの注釈（627-632 行）は「reels は part-run and paused では出さない」と区別しているので、目盛りも同じ意図だった可能性がある。

**直し方の見当**：一時停止中（`left < duration`）は目盛りを薄くして触れなくするか、動かしたら残り時間を新しい長さに置き換えると明示する。仕様の判断。

**1.0 にもあるか**：あり。

### B-12（S4）編集中に画面を回すと編集途中の変更が捨てられる

**再現手順**：ペンを押し、数字を下へ動かす（完了はまだ）。画面を横にする。

**実際の動き**：数字は横向き用に覚えている位置・大きさに滑って戻り、さっきの移動は消える。横向きで「完了」を押しても縦向き用の位置は保存されない。

**原因**：`src/Clock.tsx:855-897` のレイアウト効果で、回転により `placed` が `face` から `faceWide` に変わると `fresh` となり、`pending.current` を捨てる。縦横で別々に覚える仕様の副作用。

**直し方の見当**：回転時に `pending` があればその向きの `face` に保存してから切り替える。または仕様として受け入れる。

**1.0 にもあるか**：あり。

### B-13（S4）ストップウォッチが100時間を超えると画面からはみ出すおそれ（疑い）

**筋道**：`formatFixed`（`src/timers.ts:66-70`）は時間が3桁になると「100:00:00」と1桁増える。`src/Clock.tsx:799-810` の大きさの計算は 6 桁 + コロン 2 つ + 0.1 秒を前提にしているので、桁が増えるぶん行が約 11 % 広くなる。既定の大きさでは収まる（テストで確認：100:00:06 で左 63.8 px、右 308 px）。数字を画面いっぱいまで大きくしている場合は、約 5 % ずつ左右にはみ出す計算になる。

**1.0 にもあるか**：あり。4日以上動かし続けたときだけ。

## 4. 仕様の穴と改善案

- **裏にいる間にタイマーが終わっても知らせがない。** `src/timers.ts:85-100` は JS の `setTimeout` と `Vibration` で鳴らすので、アプリが裏にあるときやロック中は何も起きず、戻ったとき（10 秒以上遅れていれば）黙って「終了」になる。置き時計として使うぶんには前にあるが、タイマーをかけて別のアプリに移る使い方では致命的。`expo-notifications` のローカル通知を終了時刻に予約しておくのがよい。
- **端末の時計を進めると、タイマーの表示だけが先に 0 になる。** 残り時間の表示は `Date.now()`、鳴る時刻は `setTimeout`（単調時計）なので、時計を 10 分進めると表示は 10 分早く 00:00:00 になり、そのまま動いた状態で止まって見える（`endAt` はまだ先）。手で時刻を変えたときだけ。
- **設定を開いている間に裏へ行って戻ると、背景が設定の裏で動く。** `scenes/shared/host.js:124` の `visibilitychange` が表に戻ったとき `resume` を呼び、アプリ側の `paused || settingsOpen` は値が変わらないので再送されない。見えないので実害は電池だけ。
- **一時停止・再開の指示が WebView の読み込み前に来ると取りこぼす。** `src/SceneView.tsx:31-33` は `window.__ambient` がまだない間の呼び出しを捨てる。背景を切り替えた直後に設定を開くと、新しい背景は設定の裏で動き続ける。`SceneView.web.tsx` は `ready` のときに `paused` を送り直しているので、iOS 側も同じようにすればよい。
- **「完了」を押さずに裏へ行くと編集中のまま。** 戻ってくれば続きができるので問題ないが、編集中は背景切り替えや設定が隠れたまま。
- **鯉は時計のあたりを通ることが多い。** 7匹のうち平均 1.9 匹が時計の楕円（画面の約 15 %）の中にいた（6.7 分間のサンプル）。面積比なら 1 匹程度。サメ・マンタは面積比どおり。鯉は目的地までの通り道として真ん中を横切るため。避ける力（`keepClear`）を強めるかは好み。

## 5. 調べて問題なかったこと

### A. 時計
- 23:59 → 0:00 の繰り上がりと日付の変わり目：Playwright の時計で 11/9 23:59:52 → 11/10 0:00:03。日付の行も「11月9日 月曜日」→「11月10日 火曜日」に変わった。
- 12時間表示：0:30 → 12:30、12:30 → 12:30、13:05 → 1:05。午前午後の印はない（仕様）。
- 8種類のフォントで 10:00 → 11:11 → 20:08 と変えても、大きい数字のマスは動かない（B-04 の小さい文字を除く）。
- 英語の日付の最長例「Wednesday, September 30」は 375 px 幅でも切れない（scrollWidth = clientWidth = 222）。
- 色「自動」：暗い背景（鯉・マンタ・夜のサメ・神社）で白、明るい背景（浅瀬・白紙・通りすがり）で #0b0b0e。
- 時間帯・夏時間：`Date` のローカル表示を使っているだけなので、端末の設定に追従する。手で時刻を変えた場合は B-05 参照。

### B. モードの切り替え
- 左へスワイプで 時計 → タイマー → ストップウォッチ → 時計、右で逆。240 px のゆっくりしたスワイプ 6 回とも成功。
- 速く2回続けてはじく（間隔 60・120・250 ms）：どれも 2 ページ進んでストップウォッチ。
- 縦のドラッグでは変わらない。横に 180 px・縦に 12 px のななめは変わる（`failOffsetY` 16 px 未満なので仕様）。
- 編集中はスワイプが効かない。
- 切り替え直後にモード名が出て、約 2 秒で消え、日付に戻る。
- 半ページ（200 px ≒ 0.51 ページ）ちょうどの位置で離すと、戻ったり進んだりする境目なので、そこだけ結果が揺れる。仕様の範囲。

### C. タイマー
- 分の目盛りを 4 目盛り（32 px）動かすと +1 分、`duration = left = dial`。時間の目盛りを始点より先へ引くとたわんで 0 に戻る。はじくと分の目盛りは1分単位、時間の目盛りは1時間単位に止まる（6:11:00）。
- 開始 → 00:00:14、一時停止（残り 11.7 秒、ヒント「タップで再開・長押しでリセット」）、終了で「時間です」＋点滅＋トースト「タイマーが終わりました」、タップで 00:00:15 に戻る（開始はしない）、長押しで 0（目盛りも 0）、0 でタップしても何も起きずヒント「目盛りで時間を合わせて…」。
- 保存枠：空きに保存、同じ長さを2枠に保存、長さを変えてから枠をタップで呼び出し（目盛りも戻る）、長押しで削除、0 のときは「目盛りで時間を合わせてから保存してください」。
- 動作中に再読み込みしても `endAt` から続く（00:04:55）。
- 最長 23:59:45 の表示と目盛り。横向き（844×390）での目盛りの幅と英語表示。
- 目盛りのラベルは `TextInput` に animatedProps で入れているが、ウェブ版でも描けている（`timer.png`）。
- 保存枠を呼び出したあと、鳴る時刻の `setTimeout` は `endAt` が変わるたびに張り直される。

### D. ストップウォッチ
- タップで開始・停止、長押しでリセット。再読み込みしても続く。
- 100 時間後：「100:00:06.8」が既定の大きさで収まる（B-13 は最大の大きさの場合）。

### E. 数字の編集
- 2本指で広げると最大（倍率 1.41、画面幅いっぱい）で止まり、枠が紅（#d7003a）になり、振動が1回。縮めると 0.35 で止まり、同じく紅。離すと枠の色が戻る。
- 離した瞬間の数字の大きさは、動いている間（0.75 % 大きく描いて縮めている）と止まった後（ぴったり）で 1 px 以内。ゴースト（枠の外の数字）は出ない（以前の `ghost.cjs` と同じ結果）。
- 左上・右下の隅へ引きずっても、上のボタンの下（y ≥ 74）と画面内に留まる。保存される `face` は画面に対する割合。
- リセットボタンで元の位置に滑って戻り、完了で `{x:0,y:0,scale:1}`。
- 1032×1376 で右下に大きく置いた位置を、320×1024・507×1024 で開いても画面内に収まる（倍率も画面に合わせて小さくなる）。

### F. ボタン、案内、設定
- 起動から約 3.5 秒でボタンが消える。タップで出る、もう一度タップで消える、出てから 3.5 秒で消える。
- 長押しで時計が隠れてトースト、もう一度で戻る。
- 「次の背景」を2回続けて押しても 2 つ進み、古い背景の層は消える（iframe は最終的に1つ）。
- 7 つの背景を一周、「前の背景」、再読み込みで最後の背景が復元される。
- 初回の案内：1/4 → 4/4、途中で回転しても吹き出しは画面内、閉じると `tipsSeen`。設定の「使い方を見る」で 1/4 から再表示、「スキップ」で閉じる。
- 設定：秒・24時間・日付・フォントの変更がすぐ反映され、再読み込み後も残る。English にすると設定の見出し・背景の帯・日付が英語になる。
- 色の場：タップ・ドラッグ・タッチのいずれでも色が選ばれ（`clock.color` に `{h,l}`）、リングが追従する。「自動」で null に戻る。場の中の縦ドラッグは設定画面をスクロールさせず色を変える（仕様どおり）。

### G. 保存と移行
- 壊れた JSON（`{bad`）、`null`、`5`、`[]`：すべて既定値で起動（鯉・時計）。
- 存在しない背景 ID：鯉で起動（保存値はそのまま残る）。存在しないフォント ID：標準で表示。
- `face` に文字列や負の倍率：落ちずに表示（倍率は 0.35 に丸まる）。保存枠に文字列：落ちない。
- 1.0 の形（`dial` なし）の保存データ：タイマー 00:10:00 として正しく読める。
- 変更から 250 ms 以内に終了すると最後の変更が消えるのは設計どおり。ストップウォッチ・タイマーは開始時刻だけを保存するので、カウント中に保存が増えることはない。

### H. 背景
- 7 つすべて：読み込み・タップ・長押し・回転でエラーなし。1フレームの JS 時間は 390×844 で 鯉 2.7 ms、浅瀬 1.8 ms、マンタ 1.4 ms、夜のサメ 0.9 ms、神社 0.06 ms、通りすがり 0.8 ms。1376×1032 でも 2.6 ms 以下。
- 6.7 分（12000 フレーム）動かしても、魚は画面の外に出たままにならず、NaN もない。神社の落ち葉は 29 枚で安定（上限 160、休んでいる葉は 60 で間引く）。通りすがりは 120 回の標本で 2 足分より近づいたことがない（最短 2.07 足）。
- 7 日後（`Host.time = 604800`）に進めても、どの背景も NaN なし・描画あり。
- 縦 → 横の回転直後は魚が 1〜3 匹画面の外にいるが、30 秒以内に戻る。
- `pause()` で `Host.time` が止まり、`resume()` で進む。
- 神社の WebGL が使えないときの 2D 描画は、コード上はある（`useFallback`）。ウェブ版では WebGL が使えるので通っていない。
- 白紙：数字は #0b0b0e で読める。

### I. iOS の実機でしか起きないこと（コードを読んだ範囲）
- `AppState` が `inactive`（コントロールセンターなど）でも背景を止め、`active` で再開する（`App.tsx:136-139`）。
- `useKeepAwake()` は起動中ずっと有効（`App.tsx:55`）。
- ノッチ・ホームバー：`useSafeAreaInsets` でボタンと数字の可動範囲を避けている（`Clock.tsx:143-146`）。
- 振動：目盛りの1分ごとの `selectionAsync` は、はじいたとき最大 60 回／0.5 秒になるが、iOS 側でまとめられる。
- 視差効果を減らす：神社の文字の入れ替えは遅くなる（`Host.reducedMotion`）。Reanimated のばねは減らない。
- B-02・B-06 は上のとおり。

### J. その他
- 全背景・全モード・設定を一周してもコンソールのエラーなし（ウェブ版だけの警告：`useNativeDriver` 未対応、WebGL の ReadPixels の性能警告）。
- `useNow`・`hideTimer`・`AppState` の購読はすべて後片付けされている。
- 背景からのメッセージは JSON として解釈し、`type` を見て捨てている（`SceneView.tsx:38-50`）。ウェブ版は送信元の iframe も確かめている。
