## 1. プロジェクト概要

- **アプリの種類・規模**
  - ゆっくり動く背景（文字で描いた鯉の池、サメの浅瀬、すりガラス越しの通行人、白紙）の上に、大きな時計・タイマー・ストップウォッチを置く「眺める置き時計」アプリです。iPhone / iPad 向けで、App Store に ¥300 で提出中です（1回目の審査は情報の追加を求められました）。
  - ［事実］コミット70件、期間は約9日（10/26〜11/03）。アプリ側のコードはおよそ8,700行です。主な行数は `src/Clock.tsx` 1,361行、`scenes/walkers.html` 1,765行、`scenes/shared/ascii-sea.js` 1,083行です。
- **技術スタック**［事実：`package.json`・`app.json`・`eas.json`］
  - 言語：TypeScript（`strict`）。背景は素の JavaScript と HTML（Canvas と WebGL）。
  - フレームワーク：Expo SDK 58（React Native 0.88、React 19.3、New Architecture、Hermes）。
  - DB・サーバー：なし。設定は端末内の `@react-native-async-storage/async-storage` に保存し、通信もしません。
  - ビルドと配布：EAS Build / EAS Submit。App Store Connect で審査。
  - ホスティング：プライバシーポリシーだけ GitHub Pages（別の公開リポジトリ `Omni-lab26/lento`）。
  - 主要ライブラリ：
    - `react-native-reanimated` 4、`react-native-gesture-handler` 3.3、`react-native-worklets`
    - `react-native-webview`（背景を HTML で動かす）
    - `expo-blur`、`@react-native-masked-view/masked-view`、`react-native-svg`
    - `expo-haptics`、`expo-keep-awake`、`expo-localization`、`expo-splash-screen`
    - `@expo-google-fonts/*`（7書体）
  - 検証：ブラウザ版の書き出し（`expo export --platform web`）を Playwright で操作するスクリプト。［事実］ただしスクリプトはリポジトリに入れておらず、作業用の一時フォルダにありました。
  - 開発支援：ESLint（`eslint-config-expo`）、`tsc --noEmit`。テスト・CI・フォーマッター・pre-commit は**なし**です。

## 3. 最初にやるべきこと

1. **1ページの企画メモ（目的・誰向け・MVP の範囲・やらないこと）**：今回いちばん大きな手戻り（写真背景、数字表記）は、範囲を決めていなかったことから来ています。
2. **名前・バンドル ID・slug・アイコンの方向性を、仮でも決める**：あとから変えると、ストア情報、ビルド設定、保存キーまで影響します。
3. **画面と操作の一覧（各画面で、どの指の動きで何が起きるか）**：タイマーと数字の編集は、操作方法を決めないまま実装で探ったため、何度も作り直しました。
4. **実機で動く最小構成を作り、iPhone で開く**（Expo Go または開発ビルド、`npm run live` 相当）：ブラウザでは見えない問題（描画の荒さ、振動、言語）を早く見つけられます。
5. **最初の本番ビルドを TestFlight まで通す**（中身は空に近くてよい）：EAS、証明書、App Store Connect の登録、アイコン、起動画面、言語の流れを、早めに一度通しておけます。
6. **確かめ方の土台を作る**（型チェック、lint、ブラウザでの e2e、スクリーンショット）：AI に「直した」と言われたことを、すぐ確かめられるようにするためです。
7. **ブラウザで確かめられないことの一覧を作る**：AI がブラウザで「OK」と報告しても、実機で確認が必要なものを最初から分けておけます。

## 4. 最初に決めておくべきこと

### 仕様・スコープ
- MVP の範囲：今回なら「動く背景3種 ＋ 時計・タイマー・ストップウォッチ ＋ 位置と大きさの編集」。
- やらないこと：写真背景、数字表記、Apple Watch 版、Android 版（あとで）、アプリ内課金。
- 操作の基本ルール：タップ、長押し、スワイプ、ピンチにそれぞれ何を割り当てるか。今回は途中で「背景をタップするとバーが出たり消えたりする」「設定の外側をタップで閉じる」と変えていきました。
- 「完成」の基準：たとえば「実機でピンチしたとき、ちらつかない・荒れない」のように、確かめられる形で書きます。
- 収益モデル：無料か有料か、配信する国（EU の事業者表示を出すかどうか）。

### 技術選定
- フレームワーク：Expo（使う SDK のバージョン）、New Architecture。
- アニメーションと操作：Reanimated と Gesture Handler を使うか。UI スレッドで処理するのを基本にするか。今回は「JS で毎回描き直すと重い」とわかってから、途中で UI スレッドに寄せました。
- 重い描画をどこでやるか：今回は WebView の中の Canvas と WebGL。良い選択でしたが、Apple Watch 版を作るなら描き直しが必要になる、という代償を最初に知っておくべきでした。
- 言語の判定：`expo-localization` を使い、`supportedLocales` を設定する。
- 保存：AsyncStorage（データベースは不要）。保存キーに名前を入れない（`settings.v1` など）。
- 配布：EAS Build / Submit、App Store Connect。Android を出すかどうか。

### 設計・構成
- ディレクトリ構成：アプリ本体（`src/`）、背景（`scenes/`）、生成物（`*.generated.ts`）、ストア用（`store/`）、文書（`docs/`）、e2e（`e2e/`）。1つのリポジトリには1つのアプリだけを置く。
- 設定データの形（バージョン付き）と、あとから項目を足したときの補い方（今回の `withDefaults`）。
- 生成物を作るときの流れ（背景の HTML から生成物を作る）と、それをいつ実行するか。
- 大きなコンポーネントの分け方：`Clock.tsx` は1,361行で、33回のコミットで変更されています。数字の描画、編集の操作、タイマーの目盛りは、最初から別ファイルに分けておけば見通しがよかったはずです。

### ルール
- 命名：コード内の名前（ambient）と製品名（Lento）を分けて扱うことを、最初から決めておく。
- フォーマッターを使うか（使うなら最初の時点で全体に適用する）、lint のルール。
- コミットメッセージの書き方：今回の英語の説明文スタイルは良かったです。
- ブランチ運用：今回は機能ブランチ1本に70件のコミットを積み、main には合流させていません。リリースごとにタグを付ける、PR にする、などを決めておくと、審査に出したビルドとコードの対応が追いやすくなります。
- エラー処理：保存の失敗や設定の破損のときは、黙って初期値に戻す、など。
- 「完了」と言ってよい条件：型チェック・lint・e2e が通り、実機での確認が必要な項目には「未確認」と明記する。

## 6. もしゼロからやり直すなら：理想の立ち上げ手順

1. **企画を1ページに書く**
   - やること：目的、誰向け、MVP、やらないこと、収益（¥300、EU なし）、名前とバンドル ID、アイコンの方向性。
   - 完了の目安：`docs/brief.md` がコミットされている。
   - AIへの頼み方：「参考動画と目的を渡すので、MVP とやらないことの案を3つの範囲で出して。決まったら brief.md に」
2. **画面と操作の一覧を作る**
   - やること：画面ごとに、タップ・長押し・スワイプ・ピンチで何が起きるか。編集モード、設定、最初の説明。
   - 完了の目安：`docs/screens.md` があり、迷ったときにここを見れば決まる。
   - AIへの頼み方：「この brief から、画面と操作の一覧表を作って。同じ指の動きがぶつかるところを指摘して」
3. **テンプレートから作り始める**
   - やること：`create-expo-app`、`app.json`（ID、言語、暗号化、プライバシー）、`eas.json`、ESLint、フォーマッター方針、`verify` などのスクリプト、CLAUDE.md、`store/` と `docs/` の雛形。
   - 完了の目安：`npm run verify` が通る。CI が緑。
   - AIへの頼み方：「テンプレートの手順で初期化して。CLAUDE.md は brief と screens から埋めて」
4. **実機で開く**
   - やること：`npm run live`（Expo Go）で iPhone から開く。背景1つと時計だけ表示する。
   - 完了の目安：手元の iPhone で動いた。
   - AIへの頼み方：「実機で開く手順を README に書いて、手元（WSL / Mac）でそのまま動く live スクリプトを用意して」
5. **最初の TestFlight を通す**
   - やること：`eas init` → `eas build` → `eas submit`。仮のアイコン（方向性に沿ったもの）、起動画面、言語の判定を実機で確認する。
   - 完了の目安：TestFlight で入れたアプリが、日本語で起動する。
   - AIへの頼み方：「EAS と App Store Connect の手順を、1ステップずつ案内して。各画面で何を選ぶかも」
6. **一番むずかしい部分を先に作る**
   - やること：今回なら、背景3種の描画と、数字の拡大縮小の描画品質。「完成」の基準を決めて、e2e の計測と実機の確認を両方行う。
   - 完了の目安：実機で、基準（ちらつかない・荒れない・指に遅れない）を満たす。
   - AIへの頼み方：「実機でしか分からない点を先に挙げて、どう確かめるかを決めてから実装して」
7. **MVP の機能を順に作る**
   - やること：時計 → タイマー → ストップウォッチ → 編集 → 設定 → 英語対応。1機能ごとに `verify`、プレビュー、TestFlight。
   - 完了の目安：screens.md の項目がすべて実機で動く。
   - AIへの頼み方：「screens.md の次の項目を実装して。完了の前に verify を通して、実機で確認が必要な点を書いて」
8. **ストアの素材を作る**
   - やること：アイコンの仕上げ、スクリーンショット（e2e から自動で撮影）、掲載文（日本語と英語）、プライバシーポリシーの公開、審査メモ、デモ動画。
   - 完了の目安：`store/` がそろい、ポリシーの URL が開ける。
   - AIへの頼み方：「store/ の雛形を埋めて。審査メモは目的・使い方・外部サービス・地域差・規制の5項目で」
9. **提出する**
   - やること：App Store Connect への入力（言語ごと）、ビルドの選択、デモ動画の添付、提出。
   - 完了の目安：「審査待ち」になった。
   - AIへの頼み方：「画面を貼るので、各欄に何を入れるか教えて」
10. **振り返って、テンプレートを更新する**
    - やること：この文書のように、手戻りと原因を記録して、テンプレートに反映する。
    - 完了の目安：テンプレートのリポジトリが更新されている。
    - AIへの頼み方：「履歴とファイルを確認して、事実と推測を分けて振り返って」

## 7. テンプレートに入れる / 入れないもの

### 他のアプリでも使えそうなもの
- `app.json` の土台：バンドル ID の置き場所、`usesNonExemptEncryption: false`、`privacyManifests`、`expo-splash-screen`、`expo-localization`（`supportedLocales`）。
- `eas.json`：3つのプロファイル、`appVersionSource: remote`、`autoIncrement`。
- `package.json` のスクリプト：`typecheck`、`lint`、`verify`、`live`、`build:ios`（git の確認つき）。
- `scripts/live.mjs`：pull、インストール、生成、Expo 起動、WSL ならトンネル、ブランチを追いかける。
- CLAUDE.md の雛形（上の案から、アプリ固有の部分を抜いたもの）。
- `store/` の雛形：`metadata.md`（日英の欄と文字数の上限）、`privacy.html`（データを集めないアプリ用）、`README.md`（提出手順、EU・中国本土・DSA の注意）、審査メモの5項目、デモ動画の撮影手順。
- `store/tools/`：e2e からスクリーンショットを撮って、見出し付きの画像に組むスクリプト（`shots.cjs`、`frame.py`）。
- 設定の保存（`settings.tsx` の、バージョン付きキーと `withDefaults`）、言語の切り替え（`i18n.ts` と `useT`）。
- e2e の土台：Web 書き出し → 配信 → CDP でのタッチ操作 → 毎フレームの計測。
- 「実機でしか分からないこと」のチェックリスト。

### このプロジェクト固有なので入れない方がいいもの
- 背景の仕組み（`scenes/` の HTML、`ascii-sea.js`、`walkers.html`）と、WebView に同梱する生成の仕組み。
- 時計・タイマー・目盛り・数字編集の部品（`Clock.tsx`、`TimeScrubber.tsx`）。
- 数字の描画品質のための工夫（描き直しの段階、止まったときに重ねるくっきり版）。必要になったときに参考にする資料として、`docs/` に残す程度にする。
- 名前、アイコン、配色、フォントの選定、掲載文の中身。
- 有料・EU なしなどの販売の判断（判断の観点だけをテンプレートに入れる）。

## 8. どのアプリにも通用する教訓 TOP3

1. **作り始める前に「やらないこと」と「完成の基準」を書く。** 今回の手戻りでいちばん大きかったのは、範囲を決めずに作った機能（写真背景、数字表記）と、基準のないまま何度も作り直した部分（タイマー、数字の編集）でした。
2. **初日に実機と本番の流れを一度通す。** ブラウザでは「問題なし」でも、実機では荒れる・言語が違う・アイコンが古い、が起きました。TestFlight まで一度通しておけば、ストア準備の日に重なった問題（名前、ID、アイコン、言語）を早く分散して片づけられました。
3. **確かめ方をリポジトリに入れて、AI の「完了」を自動で確かめられるようにする。** 型チェック・lint・e2e を `verify` にまとめてテンプレートに入れ、「実機でしか分からないこと」の一覧を CLAUDE.md に書いておくと、AI の報告をそのまま信じてよい部分と、実機で確かめる部分を最初から分けられます。
